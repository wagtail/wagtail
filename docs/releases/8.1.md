## What's new

### Varying page responses

Wagtail can now serve more than one representation of a page at the same URL, chosen per request from the `Accept` header. This general-purpose capability can be used to render JSON responses for API clients, Markdown for AI agents, or any other format you need.

See [](varying_page_responses) for full details. This feature was developed by Albina Starykova.

## Upgrade considerations - changes affecting all projects

### Pages with an `ajax_template` now vary on `X-Requested-With`

Responses from a page that defines an `ajax_template` now include `Vary: X-Requested-With`, so that caches store the AJAX fragment and the full page separately. Previously the two could be cached under the same key, and a cache could serve the fragment to a normal browser request (or the full page to an AJAX request). Shared caches that honour `Vary` will now hold one extra entry per such page, so cache size and hit ratios may change. See [](varying_page_responses) for details.

## Upgrade considerations - deprecation of old functionality

### Removed support for Python 3.10

Python 3.10 is no longer supported as of this release; please upgrade to Python 3.11 or above before upgrading Wagtail.

## Upgrade considerations - changes to undocumented internals

### Internal admin API has been replaced

The internal API used by the admin interface's page explorer, previously available at `/admin/api/main/`, has been replaced with a minimal API built on the same foundations as the [v3 API](api_v3). The new API only provides a single endpoint for the page explorer at `/admin/api/explorer/<id>/`. The page listing, detail, and actions endpoints (e.g. `/admin/api/main/pages/<id>/action/publish/`) and the `construct_admin_api` hook have been removed. If you were relying on these, consider using the [v3 API](api_v3) instead.
