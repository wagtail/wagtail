## Upgrade considerations - changes to undocumented internals

### Change to internal `FilteredSelect` cross-field referencing

If you are using `wagtail.admin.widgets.FilteredSelect`, the `filter_field` kwarg is no longer the HTML `id` of the related field. It should be changed to the HTML `name` of the related field instead.

For most usage, this means removing the `id_` prefix from the provided value, though this will depend on your customization.

```diff
-    filter_field="id_continent",
+    filter_field="continent",
```

The widget now relies on its containing `form` element having `data-controller="w-rules"` and `data-action="change->w-rules#resolve"` attributes. Wagtail's built-in filter forms already include these.

### jQuery backed `filtered-select` widget has been removed

The undocumented internal selector for `data-widget="filtered-select"`, which attached behavior to filter the options of a select input based on the value of another field, has been removed. It has been replaced with a new Stimulus-based [`RulesController`](controller:RulesController).

Similar behavior can be achieved by replacing the following attributes.

| Attribute location        | Old                                                                  | New                                                                                     | Details                                                                                                                     |
| ------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Container element         | (no special attribute)                                               | `data-controller="w-rules"` with `data-action="change->w-rules#resolve"`                | This will be the `form` element, or a `fieldset` if the behavior is contained within a subset of fields.                    |
| Filtered `select` element | `data-widget="filtered-select"` + `data-filter-field="id_continent"` | (no special attribute)                                                                  | The related field is now referenced by its `name` in each option's rules.                                                   |
| `option` elements         | `data-filter-value="1,3"`                                            | `data-w-rules-target="enable show"` with `data-w-rules='{"continent": ["", "1", "3"]}'` | Include `""` so the option is shown when no value is selected in the related field. Options without rules are always shown. |

### `user_can_edit_snippet_type()` is removed

The undocumented `wagtail.snippets.permissions.user_can_edit_snippet_type()` function has been removed. Use the [permission policy registry](wagtail.permissions.PolicyRegistry) instead:

```python
from wagtail.permissions import policy_registry

policy_registry.get_by_type(model).user_has_any_permission(
    user, {"add", "change", "delete"}
)
```
