## What's new

### Wagtail Space 2026

Our flagship [Wagtail Space](https://wagtail.org/wagtail-space-2026/) conference returns! Coming up 18-20 November, a free virtual event for people who are improving the world through code and content. 22 presentations over two days of talks and one day of community events. [Register to join us](https://wagtail.org/releases-register) 🚀

### Python 3.15 support

This release adds formal support for [Python 3.15](https://docs.python.org/3/whatsnew/3.15.html). See the list of [compatible versions of Python](compatible_django_python_versions).

### Varying page responses

Wagtail can now serve more than one representation of a page at the same URL, chosen per request from the `Accept` header. This general-purpose capability can be used to render JSON responses for API clients, Markdown for AI agents as a form of agent readiness. This can also be set up with any other format.

See [](varying_page_responses) for full details. This feature was developed by Albina Starykova.

### API v3 improvements

We have made several improvements to the [v3 API](api_v3) preview, including support for:

 * [TypedTableBlock in v3 API](api_v3_streamfield) write requests
 * [Nested inline relations in the API](api_v3_child_relations) write requests
 * [`ImageRenditionField` for v3 API](api_v3_images)
 * [Workflow operations over the API](api_v3_workflows) for pages and snippets using `WorkflowMixin`
 * [StreamField block schemas](api_v3_schema)
 * [More API schema details](api_v3_schema) for ForeignKey, ManyToManyField, GenericRelation, and Redirects
 * Improved handling of ForeignKey schema generation for multi-level relations, multi-table inheritance, and self-references
 * Correct handling of references outside of the result set criteria for the filters `ancestor_of`, `child_of`, `descendant_of`, `translation_of`
 * More valid Markdown in [v3 API rich text](api_v3_rich_text) `markdown` output for styled text around links, line breaks, multi-paragraph quotes and nested lists
 * Skipping API setup and schema generation on startup when `wagtail.api.v3` is not installed
 * Respect page tree ordering in listings endpoint by default
 * More optimized OpenAPI schema for projects with a large number of models

Those features were implemented by Sage Abdullah, Thibaud Colas, Satyam Laheri, Albina Starykova.

### Prototype Wagtail CLI

As part of the new [v3 API](api_v3) preview, we are introducing a [prototype Wagtail CLI](https://wagtail.github.io/wagtail-cli/) to speed up and automate common operations on Wagtail projects. This command line interface currently supports interacting with live sites via the API, searching developer docs, loading agent skills, and scaffolding new projects.

For more information, read [Prototyping a new CLI for Wagtail](https://wagtail.org/blog/prototyping-a-cli-for-wagtail/).
This feature was implemented by Thibaud Colas and Sage Abdullah.

### Official agent skills

We now provide official [agent skills for developers](https://wagtail.org/ai/agent-skills-for-developers/), that work together with the CLI and the API.
They make coding agents work more effectively on Wagtail-related development tasks.

This feature was implemented by Thibaud Colas.

### SEO power tools: page metadata

Content checks now show the page's meta titles and descriptions, with their lengths measured per SEO recommendations based on typical search engine display budgets.
This is shown in the [Checks panel of the page editor](https://guide.wagtail.org/en/reference/content-checks/), and in the Checks dialog of the userbar.
Editors can also expand "View more meta tags" to inspect all of the page's SEO-relevant meta tags.

This feature was developed by Thibaud Colas, with SEO guidance from Beth Parnell. We would like to thank [Freedom of the Press Foundation](https://freedom.press/) for their sponsorship of this feature.

### Multilingual, faster sitemaps

This release improves the handling of sitemaps for multilingual sites, and documents how to set up caching for sitemaps.

 * Add alternate links to sitemap for translated pages
 * Include pages from all locales in the sitemap when internationalisation is enabled, including pages with no live, public version in the site root page's locale
 * Document how to cache the sitemap
 * Prevent error when accessing the sitemap via an unknown host and no default site is configured

Thank you to contributors Julie Rymer, Jawad Khan, and Albina Starykova for implementing those improvements. And to Beth Parnell for SEO guidance.

## Upgrade considerations - changes affecting all projects

### Pages with an `ajax_template` now vary on `X-Requested-With`

Responses from a page that defines an `ajax_template` now include `Vary: X-Requested-With`, so that caches store the AJAX fragment and the full page separately. Previously the two could be cached under the same key, and a cache could serve the fragment to a normal browser request (or the full page to an AJAX request). Shared caches that honour `Vary` will now hold one extra entry per such page, so cache size and hit ratios may change. See [](varying_page_responses) for details.

### Sitemaps include pages from all locales

When `WAGTAIL_I18N_ENABLED` is `True`, the sitemap now includes pages from the page trees of all locales of the site. Previously, only pages in the site root page's locale were listed. Sitemaps of multilingual sites may now contain more entries. See [](sitemap_multi_language_support) for details.

## Upgrade considerations - deprecation of old functionality

### Removed support for Python 3.10

Python 3.10 is no longer supported as of this release; please upgrade to Python 3.11 or above before upgrading Wagtail.

### Upcoming deprecation of the v2 API

The [v2 API](api_v2_configuration) is planned for deprecation in favor of the [v3 API](api_v3). It remains available and supported in this release, with no changes. From Wagtail 8.2, using the built-in v2 API will raise deprecation warnings, to be removed from Wagtail in version 9.0. It will also be published as a separate package for those who would like to keep using it. See the [deprecation timeline](api_v2_deprecation) and [](api_v3_migration) to plan your migration, and [share your feedback](https://github.com/wagtail/wagtail/discussions/14531) on how to improve the new API and migration process.

## Upgrade considerations - changes to undocumented internals

### Internal admin API has been replaced

The internal API used by the admin interface's page explorer, previously available at `/admin/api/main/`, has been replaced with a minimal API built on the same foundations as the [v3 API](api_v3). The new API only provides a single endpoint for the page explorer at `/admin/api/explorer/<id>/`. The page listing, detail, and actions endpoints (e.g. `/admin/api/main/pages/<id>/action/publish/`) and the `construct_admin_api` hook have been removed. If you were relying on these, consider using the [v3 API](api_v3) instead.
